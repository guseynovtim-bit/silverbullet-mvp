## QBR Tool — MVP

## Продуктовая гипотеза
QBR Tool решает проблему субъективности квартального ревью: вместо разрозненных слайдов и ручных расчётов он даёт единую структурированную оценку по 3 ролям (топ‑менеджмент, проектный офис, продуктовая команда). Ключевое отличие - автоматическая приоритизация рисков и фокус‑подсказки: система не просто показывает цифры, а говорит, на что смотреть в первую очередь (в проекте использован простой скрипт уровня MVP, который можно усилить под конкретные задачи)

## Функционал MVP
- Форма ввода данных (команда, метрики, успехи, риски, планы)
- Дашборд ключевых показателей с оценкой статуса + AI-резюме квартала

## Стек
- Frontend: React + Tailwind
- Backend: Node.js
- Хранение: in-memory / простой JSON-файл
- AI:
    - персональный ассистент - Алиса AI (платная подписка): рассуждения и валидация гипотез, написание инструкций
    - Claude.ai - верификация кода, быстрая встроенная проверка макетов
    - Cursor (десктопная версия, GROK) - написание и исправление кода

## AI-лог
Промт работы с персональным ассистентом Алиса AI:
- прототип инструмента для проведения QBR (QBR-tool)
- Цель: продемонстрировать простоту структурирования квартального отчёта продуктовыми командами при условии наличия ключевых метрик
- Задача: я хочу выполнить условия задания таким образом, чтобы не усложнять код и интеграции самого MVP, больше сфокусировавшись на ценности которую действительно может принести такой подход (имеется в виду, структурный квартальный отчёт), при этом выполнить формальные требования задания
- Продуктовая гипотеза: делаем инструмент, который позволяет ввести серию ключевых квартальных итогов, и на основе вложенной логики и AI-ассистента помочь получить отчёт за квартал
- Подход: Предложить набор метрик и вложенную внутрь прототипа логику, которая с помощью AI инструментов может быть относительно легко интерпретирована тремя типами пользователей. Топ-менеджменту будет показывать оценку затрат и доходы, команде проектного офиса будет показывать качество выполнения квартального плана и утилизацию, продуктовой команде состояние продуктовых метрик и достижение.
короткое описание дизайна
- 1. первый экран - как и написано в задании - ввод метрик и планов
- предлагаю сделать на одном экране, поскольку задача имеет всё же проверочное, а не прикладное значение - и мне, и потенциальному пользователю проще будет на одном экране ввести показатель (не важно, выдуманный или реальный), и в поле рядом ввести план по этому показателю
- в задании фигурирует требование помочь "владельцам продуктов и тимлидам", поэтому предложу набор из продуктовых и сопровождающих, а также финансовых метрик: MAU, ARPU, доля MAU от общей аудитории (конверсия), отток, размер команды, число выполненных задач в размере, количество проблемных релизов за квартал, запланированные задачи в размере
- 2. логика за первым экраном: перемножение MAU на ARPU можно отразить как объем выручки, не спрашивая про это напрямую; размер команды можно измерить в числе спринтов/размере задач, и соответственно делать расчёт утилизации
- 3. второй экран: прогресс бары по каждой из метрик и карточки со сводкой и статусами (ok/risk/attention), каждая карточка имеет кнопку AI-резюме, при нажатии которой дается оценка именно этой карточки в терминах "почему именно ok/risk/attention". поверху всей страницы короткий HTML-блок с AI-резюме, который даёт оценку всего квартала и подсказывает на какую карточку/статус обратить отдельное внимание
- рассуждай как опытный продуктовый архитектор, насколько это хорошая цель, задача, подход, гипотеза и план?

Промт для AI-резюме квартала. Промпт спроектирован так, чтобы AI давал выводы сразу для трёх ролей, экономя время фокусировке - в идеале каждая роль легко опознаёт себя в описании и ознакамливается с самым важным, при этом не теряется окружающий контекст.
- Рассуждай как опытный директор по продукту в крупной технологической компании. Твоя задача проанализировать итоги квартала на основе предоставленных данных и сформулировать краткое, но содержательное резюме для трёх разных аудиторий.
- Входные данные (JSON):
- {json_input}
- Требования к ответу:
- 1. Общий итог квартала (1–2 предложения): коротко и ёмко что получилось, на что важно обратить внимание - используй в качестве контекста все данные.
  2. 2. Для топ‑менеджмента (1 абзац): фокус на деньгах и масштабе (MAU, ARPU, выручка‑эквивалент, риски по деньгам). Используй только данные из JSON. Не придумывай цифры.
  3. 3. Для проектного офиса (1 абзац): фокус на исполнении (задачи, релизы, загрузка команды, отставания).
  4. 4. Для продуктовой команды (1 абзац): фокус на продукте (конверсия, отток, достижения, планы).
- Формат вывода строго JSON:
- {
- "summary_overall": "...",
- "for_c_level": "...",
- "for_project_office": "...",
- "for_product_team": "..."
- }
-
- Тон: деловой, но понятный нетехническим сотрудникам. Избегай жаргона. Статусы OK/Risk/Attention используй только если они явно следуют из данных.
