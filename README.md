## QBR Tool — MVP

## Продуктовая гипотеза
QBR Tool решает проблему субъективности квартального ревью: вместо разрозненных слайдов и ручных расчётов он даёт единую структурированную оценку по 3 ролям (топ‑менеджмент, проектный офис, продуктовая команда). Ключевое отличие - автоматическая приоритизация рисков и фокус‑подсказки: система не просто показывает цифры, а говорит, на что смотреть в первую очередь

## Функционал MVP
- Форма ввода данных (команда, метрики, успехи, риски, планы)
- Дашборд ключевых показателей с оценкой статуса + AI-резюме квартала

## Стек
- Frontend: React + Tailwind
- Backend: Node.js
- Хранение: in-memory / простой JSON-файл
- AI:
    - персональный ассистент - Алиса AI (платная подписка): рассуждения и валидация гипотез
    - Claude.ai - написание и верификация кода, быстрая встроенная проверка макетов

## AI-лог
Промт проверки кода FormQBR_v01.jsx:
- Оцени предложенный код как Senior fullstack разработчик и архитектор веб-приложений, предложи исправления.

Промт проверки кода dashboards.jsx:
- Выступай как Senior fullstack разработчик, с учётом контекста исправлений в файле FormQBR.jsx, оцени качество кода и предложи соответствующие исправления в коде Dashboards.jsx, который должен отражать отчёт по метрикам из FormQBR.jsx

- Промт для AI-резюме квартала. Промпт спроектирован так, чтобы AI давал выводы сразу для трёх ролей, экономя время фокусировке - в идеале каждая роль легко опознаёт себя в описании и ознакамливается с самым важным, при этом не теряется окружающий контекст.
Рассуждай как опытный директор по продукту в крупной технологической компании. Твоя задача проанализировать итоги квартала на основе предоставленных данных и сформулировать краткое, но содержательное резюме для трёх разных аудиторий.  

Входные данные (JSON):
{json_input}

Требования к ответу:
1. Общий итог квартала (1–2 предложения): коротко и ёмко что получилось, на что важно обратить внимание - используй в качестве контекста все данные.
2. Для топ‑менеджмента (1 абзац): фокус на деньгах и масштабе (MAU, ARPU, выручка‑эквивалент, риски по деньгам). Используй только данные из JSON. Не придумывай цифры.
3. Для проектного офиса (1 абзац): фокус на исполнении (задачи, релизы, загрузка команды, отставания).
4. Для продуктовой команды (1 абзац): фокус на продукте (конверсия, отток, достижения, планы).

Формат вывода строго JSON:
{
  "summary_overall": "...",
  "for_c_level": "...",
  "for_project_office": "...",
  "for_product_team": "..."
}
